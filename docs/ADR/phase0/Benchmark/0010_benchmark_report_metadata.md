# ADR 0010: Benchmark Report Metadata Headers

- **Status**: Draft
- **Date**: 2025-09-28
- **Owners**: Tasqly Team
- **Related**: ADR 0009 (Benchmark Log Cleanup)
- **Tags**: benchmarks, reporting, metadata

---

## Context

Benchmark reports generated by the `run_bench_mingw_release.py` and `run_bench_msvc_release.py` scripts originally contained only benchmark results (tables and charts). While useful, these reports lacked contextual information about the environment, making it harder to interpret results when viewed later or by other team members.

As Tasqly benchmarks are regularly executed under both **MinGW** and **MSVC** toolchains, it became important to add explicit metadata that identifies the environment and system characteristics used during the benchmark run.

## Decision

We updated the benchmark runner scripts (`run_bench_mingw_release.py`, `run_bench_msvc_release.py`) to prepend a **Metadata Header** to each Markdown report, containing:

- **Environment**: Explicit label (`MinGW Performance Benchmark` or `MSVC Performance Benchmark`).
- **Phase**: Benchmark phase name (`phase0`, `phase1`, ...).
- **Host**: Machine hostname.
- **CPU**: Number of cores and frequency.
- **Runner**: Path to the benchmark runner executable.
- **Generated On**: Timestamp of report generation.

This header is written before any benchmark tables or charts, ensuring the report is self-explanatory and portable.

## Consequences

- ✅ **Benefits**:
  - Readers immediately know whether results are from MinGW or MSVC.
  - Reports are self-contained and carry environment context.
  - Easier to compare and archive reports across different systems or phases.

- ⚠️ **Drawbacks**:
  - Slightly longer Markdown files (a few extra lines at the top).
  - Hardcoded environment labels (MinGW/MSVC only).

- 🔄 **Trade-offs**:
  - We chose clarity and explicit labeling over automation. Since only MinGW and MSVC environments are supported locally, automatic detection was unnecessary.
